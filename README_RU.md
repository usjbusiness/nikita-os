# Nikita OS 3 — Premium

Самостоятельное PWA на Vercel + Supabase. Графитовая тема, широкое расписание, цветные категории, простые задания и компактные переходы.

## Обновить уже работающий сайт — без новой настройки Supabase

1. На текущем сайте открой **Настройки → Скачать JSON-копию**. Сохрани её у себя перед обновлением.
2. Распакуй новый ZIP. Открой папку `nikita-os`.
3. В своём **приватном** GitHub-репозитории замени файлы сайта содержимым этой папки. Загружай содержимое, а не сам ZIP и не внешнюю папку.
4. В корне репозитория должны лежать `package.json`, `vercel.json`, `seed.json`, **`validation.mjs` и `migrations.mjs`**, папки `api`, `lib`, `public`, `scripts`, `tests`, `supabase`.
5. Важно обновить и серверные файлы, и public/. Не ограничивайся только CSS или app.js.
6. Vercel запустит новый deployment по GitHub commit. Дождись **Ready** у самого нового deployment. Если автоматический запуск не произошёл: Deployments → ⋯ → Redeploy.
7. Открой основной адрес https://nikita-os-azure.vercel.app и обнови страницу. Установленное приложение закрой полностью и открой снова.

**Пять переменных Vercel оставь без изменений. Новые ключи, новый проект и новый SQL не нужны. Не удаляй nos_state и не восстанавливай seed.json поверх живых данных.**

Если новая версия не появилась, открой сайт в обычном браузере, обнови его и затем перезапусти установленное приложение. Новая оболочка использует отдельную версию service worker.

## Что изменилось

### Главная / расписание
- Сразу наверху — выделенные быстрые кнопки избранных сайтов.
- Под ними — расписание на всю доступную ширину, без боковой колонки задач и без большого приветственного баннера.
- Показаны **все записи выбранного дня**, а не первые восемь. Есть время, план, место, категория и исходные логотипы.
- Наверху расписания — заметная кнопка **«Добавить событие»**. Ещё одна кнопка **«+ Событие»** постоянно находится в верхней панели.
- Новое событие создаётся на выбранную в расписании дату. В редакторе дату можно изменить.
- «Сегодня» возвращает текущую дату, стрелки переключают недели, дни в полосе — выбранный день.
- При первом открытии показывается сегодня, если на сегодня есть записи. Иначе — ближайший будущий день с записями, а если будущих нет — последний заполненный день. Фактическая дата всегда указана в заголовке.
- Внизу расписания указан диапазон дат, реально имеющийся в базе. Автоматической генерации недостающих недель нет.

### Цвета
Оболочка — нейтральный графит и светло-серые/ледяные кнопки, без зелёных панелей.
- Хоккей и тренировки — синий.
- Занятия — золотистый.
- Матчи — бордово-розовый, метка «ВАЖНО».
- Athletic Training — фиолетовый.
- Business Society — отдельный сине-стальной акцент и свой логотип.
- Другие важные события — тёплый медный.
- Дорога — нейтральный тёплый фон, свободное время — спокойный графит.

### Задания и дела
- **Учебные задания** — отдельный список, сгруппированный по календарным датам сдачи.
- **Личные дела** — отдельный простой список.
- Для учебного задания достаточно написать название, при необходимости предмет и дату, нажать «Добавить».
- Личное дело добавляется одной строкой.
- Одна галочка завершает задачу. Во вкладке «Выполнено» можно вернуть её обратно.
- Нажатие названия открывает редактирование. Тип списка можно поменять вручную.
- Приоритет, ссылка и заметки находятся в «Дополнительно».
- Старые даты не переписаны и не выданы за актуальные: отмечены «Проверь старый срок». Их нужно сверить с Blackboard.
- Старые задания с заполненным предметом отнесены к учебным; без предмета — к личным. Исходная заметка про poetry annotation также отнесена к учебным. При необходимости список можно исправить в редакторе.

### Сайты и формы
- Компактные строки вместо высоких карточек.
- Избранное дополнительно выделено отдельной панелью.
- ★ добавляет ссылку в быстрый доступ. На главной — первые шесть избранных; в верхнем меню — первые восемь.
- Все ссылки доступны в полном разделе; редактирование и добавление сохранены.

### Вход / загрузка
- Минимальный экран входа: знак, поле кода и кнопка, без длинных слоганов.
- Загрузочный экран — знак N/OS и тонкий индикатор, без большого текста.
- Установочные иконки обновлены в новой палитре.

## Перенос игры в существующей базе

При первом авторизованном открытии версии 3 сервер выполнит одноразовое обновление:
- Исходная игра **vs. EHL All Stars · Home** переносится со **среды 21 октября 2026** на **вторник 20 октября 2026**.
- Неизвестное время остаётся неизвестным: новое время не выдумано.
- Меняется только исходная запись с её точным ID и только если она всё ещё стоит 21 октября. Уже вручную перенесённая на другой день игра не переопределяется.
- Другие игры, записи, задачи, заметки и ссылки сохраняются. Запись Supabase целиком не сбрасывается.
- В документе хранится маркер миграции; ручной перенос игры после обновления не будет отменён при следующем входе.
- Сохранение проверяет номер ревизии; конфликт не перезаписывает чужую более свежую запись.

**Это изменение по твоему указанию, не подтверждение обновления HOULI.** Автосинхронизация с HOULI, Notion и Blackboard не подключена.

## Почему раньше было не всё расписание

Главный экран версии 2 показывал только первые восемь записей выбранного дня. Полный день был только в календаре. Версия 3 снимает это ограничение.

Кроме того, исходно перенесён снимок **19–25 октября 2026**, а не весь семестр. При обновлении твои добавленные даты сохранятся. Но неизвестные события и расписание будущих недель приложение само не придумывает: добавляй их через «Добавить событие» и повторы либо вноси новые данные вручную.

## Если устанавливаешь с нуля

1. Создай Supabase-проект; выполни весь `supabase/setup.sql` в SQL Editor.
2. Если API ещё не видит созданные функции, выполни:

```sql
NOTIFY pgrst, 'reload schema';
```

3. Загрузи проект в приватный GitHub-репозиторий, импортируй в Vercel.
4. Framework **Other**; Node.js **24.x**; Build `npm run build`; Output `public`; Root — папка с vercel.json.
5. Vercel → Settings → Environment Variables → Production:

| Имя | Значение |
| --- | --- |
| SUPABASE_URL | Только `https://идентификатор.supabase.co`, **без /rest/v1/** |
| SUPABASE_SECRET_KEY | Серверный Secret key из того же проекта Supabase; обычно sb_secret_… |
| APP_PIN | Личный код из 8–12 цифр |
| SESSION_SECRET | Случайная строка минимум 32 символа |
| APP_URL | Основной HTTPS-адрес приложения без конечного слеша |

6. Redeploy после добавления/изменения переменных. Открой APP_URL и войди по APP_PIN.
7. При первом запуске пустая nos_state заполняется исходными данными автоматически. Если строка уже есть, seed не заменяет её.

**Секреты не добавляй в GitHub, HTML, public/app.js и чат.** У переменных нет префиксов NEXT_PUBLIC_ / VITE_. Ключ Supabase используется только сервером.

## Установить приложение

Открой опубликованный HTTPS-сайт в обычном браузере:
- iPhone/iPad: Safari → Поделиться → На экран «Домой» → Добавить.
- Android: Chrome → ⋮ → Установить приложение.
- Windows/Mac: Chrome/Edge → значок установки или меню «Установить приложение».
- Safari на поддерживаемой macOS: Файл → Добавить в Dock.

Если приложение уже установлено, переустанавливать его обычно не нужно. Обнови сайт и полностью закрой/открой приложение. App Store, APK и IPA не требуются.

## Данные и ограничения

- Хранение: Supabase Postgres. API: Vercel Functions. Railway, Docker, SQLite и отдельный сервер не нужны.
- Сессия по коду: до 30 дней, cookie HttpOnly / Secure / SameSite Strict. Код проверяется только сервером.
- 8 попыток в 15 минут; лимит общий для личного приложения. Смена PIN + Redeploy аннулирует старые сессии.
- API не кэшируется офлайн. Для загрузки и сохранения данных нужен интернет.
- Между устройствами хранилище общее, но для получения новых изменений нужно обновить страницу; realtime-подписки не подключены.
- Планировщик следующего семестра не регистрирует на курсы: регистрация в MyUSJ.
- Сохраняй JSON-копии приватно. Импорт полностью заменяет данные только после подтверждения.
- Исходные 85 событий, 16 задач и 9 ссылок — снимок, не поток актуальных университетских данных.
- База не имеет сквозного шифрования; владелец серверного ключа имеет доступ к данным.

## Проверка и локальная разработка

Node.js 24. Скопируй .env.example в .env.local и заполни свои значения. Для разработки APP_URL=http://localhost:3000, NODE_ENV=development. Нужен настроенный Supabase.

```bash
npm run build
npm test
npm start
```

Публикация этого обновления в аккаунтах пользователя не выполнялась автоматически. Тесты используют отдельный mock-адаптер; это не подтверждение работы с твоей живой базой.
