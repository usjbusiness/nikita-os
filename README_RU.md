# Nikita OS 2.0 — Vercel + Supabase

Обновлённое личное устанавливаемое веб-приложение. **Vercel размещает сайт и серверные функции, Supabase хранит данные. Railway, Docker, SQLite и постоянный диск Vercel не нужны.**

Архив подготовлен для публикации, но не опубликован в твоих аккаунтах: для этого нужны твой проект Supabase и проект Vercel. Рабочий код доступа и ключи в поставку не включены.

## Что изменено в 2.0

- Хранение перенесено в Supabase Postgres; API — Vercel Functions.
- Оригинальные логотипы из твоего недельного расписания добавлены в локальные файлы, без внешних CDN: USJ Blue Jays, эмблема USJ и Business Society.
- Тренировки/командные события — полноширинные синие строки; игры — усиленный синий блок с золотой меткой; Athletic Training — фиолетовый; занятия — золотистый; Business Society — тёмно-синий с собственным знаком.
- У события есть флажок **«Важное мероприятие»** и выбор логотипа. Можно самостоятельно выделять важные записи.
- На главной — **«Быстрый доступ»** с прямыми кнопками избранных сайтов.
- Вверху каждого раздела — раскрывающееся меню быстрых переходов; на телефоне это кнопка со стрелкой.
- Полный раздел **«Сайты и формы»** сохранён. Звёздочка ★ добавляет/убирает ссылку из быстрого доступа. На главной показываются первые 6 избранных, в верхнем меню — первые 8; полный список не ограничен этим.
- В редакторе ссылки можно включить избранное и выбрать логотип.

Сохранились: календарь, редактирование событий, повторы, задачи и статусы, планирование курсов с проверкой пересечений, персональный фокус, заметки, хоккейный центр, резервные копии и установка PWA.

## Быстрый запуск

### 1. Supabase: подготовить базу

1. Открой https://supabase.com/dashboard и создай проект либо выбери существующий. Для личных данных предпочтителен отдельный проект.
2. Открой **SQL Editor → New query**.
3. Из архива открой **`supabase/setup.sql`**, скопируй весь текст в SQL Editor и нажми **Run**.
4. Скрипт создаёт только три таблицы с префиксом `nos_` и две функции. Другие таблицы проекта не удаляются и не меняются.
5. В **Project Settings / Data API / Connect** найди **Project URL** вида `https://…supabase.co`.
6. В **Settings → API Keys** создай/скопируй **Secret key** вида `sb_secret_…`. Старый `service_role` тоже поддерживается, но новый Secret key предпочтительнее.

**Не используй Publishable / anon key для серверного доступа. Не вставляй Secret key в public/app.js, HTML, GitHub или чат.** Он нужен только серверной функции Vercel.

#### Как закрыты данные

- RLS включён на всех трёх таблицах.
- У `anon` и `authenticated` нет разрешений читать или менять эти таблицы.
- Браузер не обращается к Supabase напрямую и не получает ключ Supabase.
- Vercel проверяет код/сессию, затем обращается к Supabase серверным ключом.
- Это **однопользовательское приложение с PIN-входом**, не многопользовательская система Supabase Auth. Отдельно создавать пользователя в Supabase Authentication не нужно.

### 2. GitHub: загрузить обновлённые файлы

1. Распакуй ZIP.
2. Создай **Private**-репозиторий либо полностью замени код старого проекта на содержимое новой папки `nikita-os`.
3. В корне должны лежать `package.json`, `vercel.json`, `seed.json`, `validation.mjs`, папки `api`, `lib`, `public`, `supabase`, `scripts`, `tests`.
4. Не загружай сам ZIP вместо распакованных файлов. Сохраняй вложенные папки.
5. Если обновляешь прошлую версию, не оставляй старые Dockerfile, railway.json или SQLite-сервер поверх новой версии.

**Репозиторий — Private:** seed.json содержит твои исходные расписание, задания и ссылки.

### 3. Vercel: импортировать проект

1. https://vercel.com/ → **Add New → Project** → импортируй репозиторий.
2. Framework Preset: **Other**.
3. Root Directory: корень папки, в которой лежит `vercel.json`. Если загружена лишняя папка сверху, выбери её как Root Directory.
4. Build Command: **`npm run build`**.
5. Output Directory: **`public`**.
6. Node.js: **24.x**.

Настройки уже прописаны в vercel.json. **Не выбирай статическую публикацию только public/** — папка api/ тоже нужна: Vercel автоматически создаёт серверную функцию.

### 4. Vercel: переменные окружения

В **Project → Settings → Environment Variables** добавь для **Production**:

| Имя | Значение |
| --- | --- |
| `SUPABASE_URL` | Project URL из Supabase: `https://…supabase.co` |
| `SUPABASE_SECRET_KEY` | Secret key `sb_secret_…` из Supabase; только серверная переменная |
| `APP_PIN` | Твой код из **8–12 цифр**; лучше случайный, не дата рождения |
| `SESSION_SECRET` | Длинная случайная строка, минимум 32 символа; сгенерируй менеджером паролей |
| `APP_URL` | Точный основной HTTPS-адрес сайта в Vercel, без `/` в конце |

**Никаких префиксов `NEXT_PUBLIC_` или `VITE_` для секретных переменных.** Эти значения не должны попадать в браузер. PORT, DATA_DIR и диск не нужны.

Если адрес ещё неизвестен, сначала создай Deploy, посмотри основной домен в **Settings → Domains**, задай его в APP_URL и выполни **Redeploy**. До этого приложение покажет, что сервер не настроен. Используй основной Production-домен, а не меняющийся адрес отдельного deployment.

После изменения переменных всегда делай **Redeploy** — старый deployment не получает их автоматически.

### 5. Проверить

1. Открой основной HTTPS-адрес.
2. Введи APP_PIN. При первом успешном открытии сервер сам перенесёт исходные данные из seed.json в `nos_state`.
3. Создай тестовую задачу и обнови страницу.
4. Открой тот же адрес на телефоне; войди тем же кодом.
5. В Supabase **Table Editor → nos_state** будет одна строка с JSON-данными и номером версии. Это ожидаемо: интерфейс управляет записями внутри этого документа.
6. Нажми звёздочку у любой ссылки в «Сайты и формы» и проверь главный экран/верхнее меню.
7. Открой 21 октября и 23 октября в календаре: увидишь игру, синие тренировки, золотистые занятия и фиолетовую встречу с Марком.

## Установить на телефон/компьютер

После публикации открой **свой сайт**, не локальный HTML-файл и не окно внутри Notion.

- **iPhone/iPad:** Safari → Поделиться → **На экран «Домой»** → Добавить. Если есть настройка «Открывать как веб-приложение», включи.
- **Android:** Chrome → ⋮ → **Установить приложение / Добавить на главный экран**.
- **Windows/macOS:** Chrome или Edge → значок установки в адресной строке; либо меню браузера «Установить приложение».
- **Safari на поддерживаемой macOS:** Файл → Добавить в Dock.

Это PWA с собственной иконкой и отдельным окном. App Store/Google Play, APK и IPA не нужны. На телефон не нужно ставить Node.js, Supabase или Vercel.

## Быстрые переходы

- **Главная → Быстрый доступ:** прямые кнопки избранных сайтов. На телефоне полоса прокручивается вбок.
- **Верхняя панель → Быстрый доступ:** доступен из любого раздела. На телефоне — кнопка со стрелкой рядом с «+».
- **Сайты и формы:** все ссылки по категориям, включая те, которые не выбраны в избранное.
- **★ / ☆:** включить или убрать из быстрого доступа.
- **Редактировать → Логотип:** автоматический, USJ Blue Jays, USJ, Business Society или без логотипа.
- На главной — первые 6 избранных ссылок в порядке списка; в верхнем меню — первые 8.

Точные адреса E-Board/Members не были предоставлены — они не выдуманы. Их можно добавить самому через «Добавить ссылку» и включить ★.

## Расписание: логотипы и выделение

- **Хоккей:** синяя строка и Blue Jays.
- **Игра:** усиленный синий блок, золотая метка, Blue Jays, флажок важного события у перенесённых игр.
- **Athletic Training / Mark:** фиолетовая строка и Blue Jays.
- **Занятие:** золотистая строка и эмблема USJ.
- **Общество:** собственный логотип Business Society и тёмно-синий акцент.
- **Другое важное событие:** тёплый контрастный фон и метка «ВАЖНО».

Нажми событие, чтобы изменить категорию, логотип или флажок **«Важное мероприятие»**. Выделение не зависит только от цвета: есть текст категории, логотип и метка.

Логотипы скопированы из твоего исходного блока расписания. Новый или одобренный брендинг организации не предполагается; это оформление личного приложения.

## Перенос из версии 1

Если уже вводил новые данные в первую версию:

1. В старом приложении: **Настройки → Скачать JSON-копию**.
2. Разверни версию 2.
3. В новой: **Настройки → Восстановить из копии**.
4. Подтверди полную замену данных.

Формат старых копий поддерживается. Логотипы восстановленных событий по умолчанию определяются автоматически. В старых копиях нет избранного: после восстановления отметь нужные ссылки звёздочкой. Если приложение уже использует Supabase, обновление кода не перезаписывает существующую строку nos_state.

В поставке: 85 событий на 19–25 октября 2026, 16 исходных задач, 9 ссылок, фокус-план и хоккейный центр. Старые сроки заданий и исходные статусы требуют проверки. Изменения, которые старые HTML-виджеты хранили только в localStorage, недоступны при переносе. Встреча с Марком — пятница 23 октября, 12:30–13:00. Время игр 21 и 24 октября по-прежнему не указано.

## Безопасность и хранение

- Сессия на доверенном устройстве сохраняется 30 дней; cookie HttpOnly / Secure / SameSite=Strict.
- Код проверяет сервер. В HTML и исходном frontend-коде PIN отсутствует.
- Проверка попыток входа хранится в Supabase и атомарна: она работает между разными экземплярами serverless-функции, а не только в оперативной памяти Vercel.
- После 8 попыток в 15-минутном окне вход временно блокируется для всего личного приложения. Успешный вход сбрасывает счётчик. Посторонний человек может временно исчерпать лимит — это компромисс простого PIN-входа.
- Смена APP_PIN или SESSION_SECRET + Redeploy прекращает действие прежних сессий. Данные не удаляются.
- APP_URL должен совпадать с основным адресом сайта: запросы изменения с другого Origin блокируются.
- Хранение в Supabase не является сквозным шифрованием. Администраторы проекта и владельцы Secret key имеют доступ к данным.
- Регулярно скачивай JSON-копию и храни приватно. Она не содержит PIN, SESSION_SECRET или ключ Supabase.
- Удаление проекта/таблицы Supabase удалит данные. Следи за доступностью и условиями тарифа Vercel/Supabase; бессрочная бесплатная работа не гарантируется.

## Ограничения

- Нет автоматической синхронизации с Blackboard, Notion, HOULI и MyUSJ. Данные перенесены как снимок, дальнейшие изменения вводятся вручную.
- Регистрация на курсы выполняется в MyUSJ; здесь — планирование и проверка пересечений.
- Часовой пояс расписания — America/New_York.
- Нет push-напоминаний, оплаты, многопользовательских аккаунтов и загрузки файлов; доступны ссылки на файлы.
- Для загрузки и сохранения личных данных нужен интернет. Service worker кэширует только оболочку и логотипы, не API-ответы с данными.
- Открытый экран другого устройства обнови для получения новых правок. При конфликте версий приложение загрузит свежие данные и предложит повторить изменение.

## Локальная разработка (необязательно)

Node.js 24. Создай `.env.local` рядом с package.json, заполнив значения из .env.example. Для локального запуска используй `APP_URL=http://localhost:3000` и `NODE_ENV=development`. Ключ остаётся только на локальном сервере, не в браузере. Нужен настроенный проект Supabase и выполненный setup.sql.

```bash
npm start
```

Открой http://localhost:3000. Не коммить .env.local. Для телефона используй опубликованный HTTPS-сайт.

Проверки без настоящих секретов:

```bash
npm run build
npm test
```

Тесты используют отдельный mock-адаптер хранилища; production-функция не имеет режима обхода входа и не переключается на mock по переменной окружения.

## Если возникла ошибка

| Симптом | Что проверить |
| --- | --- |
| «Сайт ещё не настроен» | Все 5 переменных заданы для Production; выполнен Redeploy. |
| «Проверь SUPABASE_URL / SUPABASE_SECRET_KEY и выполни setup.sql» | URL/Secret key из одного проекта; SQL выполнен полностью; проект Supabase доступен и не приостановлен. |
| Вход даёт 404 / API возвращает HTML | В репозитории есть api/handler.js и vercel.json; Root Directory правильная; Framework Other, Output Directory public. |
| «Адрес сайта не совпадает с APP_URL» | Открывай основной домен из APP_URL; после смены домена измени APP_URL и сделай Redeploy. |
| После неверных кодов не пускает даже с верным | Подожди до конца 15-минутного окна. При забытом PIN смени APP_PIN; сам лимит продолжает храниться в базе. |
| Новые данные не видны на другом устройстве | Обнови страницу. Сохранение общее, но мгновенные realtime-события не подключены. |
| Нет логотипов | Загружена папка public/brands целиком, регистр имён совпадает; закрой/открой установленное приложение. |
| Не устанавливается на iPhone | HTTPS и Safari; не встроенный браузер другого приложения. |
| После обновления старое оформление | Закрой приложение полностью и открой снова. При необходимости очисти данные сайта и войди повторно — записи останутся в Supabase. |

## Карта файлов

- `vercel.json` — маршруты API, заголовки и сборка Vercel.
- `api/handler.js` — единая серверная функция.
- `lib/handler.mjs` — PIN-вход, сессии и API.
- `lib/store.mjs` — серверные запросы в Supabase REST API.
- `supabase/setup.sql` — таблицы, RLS и атомарные функции.
- `public/` — сайт, PWA, логотипы и иконки.
- `seed.json` — исходные личные данные, только для первого запуска.
- `validation.mjs` — проверка данных, включая старые копии.
- `server.mjs` — локальный сервер, не используется для запуска на Vercel.
- `tests/` — автономные тесты API и адаптера.
