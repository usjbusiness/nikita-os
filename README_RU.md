# Nikita OS 4.0.0 — Focus

Личный планировщик для учёбы и хоккея. Vercel + Supabase, без Railway.
**Обновление существующего сайта:** сначала прочитай `ОБНОВЛЕНИЕ.txt`.
В архиве файлы лежат сразу в корне — дополнительная папка не нужна.

## Главное
- Избранные сайты → «Сейчас / дальше» → полное расписание на всю ширину.
- Реальное время Нью-Йорка. Блок «Сейчас / дальше» обновляется раз в минуту,
  не перезагружая форму. События без времени не получают выдуманную длительность.
- При просмотре другого дня явно указано, какой это день. Сегодня не подменяется
  исторической датой. Начальная страница выбирает сегодня или ближайший день
  с имеющимися записями; если будущих записей нет — последний заполненный день.
- Цвета — категории и важность, не обещания психологического эффекта:
  синий — хоккей, янтарный — занятия, лавандовый — Athletic Training,
  розовый — игры, красноватое предупреждение — пересечение записей.
- Учебные задания группируются по сроку. Сроки старше семи дней свёрнуты,
  но не удалены; поиск раскрывает их. Личные дела — отдельный простой список.
- Отметка завершения задачи отменяется кнопкой в уведомлении (около 5 секунд),
  либо через вкладку «Выполнено». Добавление — прямо в списке.
- Короткий необязательный ориентир перед льдом: действие, слово, первый шаг;
  после — что получилось и одна корректировка. Дата записи видна.
- Самоотметки самочувствия необязательны, не заполняются заранее и не дают
  допуска к нагрузке или медицинского заключения. Это не психологическая терапия.
- Настройки показывают версию, время последней загрузки/сохранения,
  резервную копию и проверку новой опубликованной сборки.
- `/version.json` и `/update-check.html` публичны, но содержат только версию,
  никаких данных, ключей или сведений о конфигурации.

## Надёжность данных
Серверная сессия с HttpOnly Secure SameSite=Strict cookie на 30 дней.
PIN и секреты остаются на сервере. Ограничение попыток входа хранится в Supabase.
Запись состояния проверяет revision: конфликт другого устройства не затирает его
изменения молча. Данные других устройств загружаются при открытии сайта либо
кнопкой обновления в блоке «Сейчас / дальше»; realtime-канала здесь нет.

В service worker хранится только оболочка, логотипы и иконки, не API и не
личные данные. Без подключения личные записи не открываются из офлайн-кэша.
«Перезагрузить интерфейс» удаляет только shell-кэши приложения.

Полнота: исходный снимок расписания — 19–25 октября 2026; курсы на весь семестр
нужно добавить самостоятельно или создать повторы с явной датой окончания.
Blackboard, HOULI, MyUSJ и Notion автоматически не синхронизируются.
Статусы и сроки старых заданий нужно проверить. Цвета не заменяют подписи.

## Для новой установки
Для существующего проекта этот раздел повторять НЕ нужно.
1. Создай проект Supabase и выполни содержимое `supabase/setup.sql` в SQL Editor.
2. Загрузи все файлы в корень GitHub-репозитория. Импортируй его в Vercel.
3. Framework Other, Node.js 24.x, Root Directory корень, Output Directory public.
4. В Vercel добавь только серверные переменные из `.env.example`:
   - SUPABASE_URL: корень `https://<project>.supabase.co`, без `/rest/v1/`.
   - SUPABASE_SECRET_KEY: серверный secret key или legacy service_role.
   - APP_PIN: свой код из 8–12 цифр, не публиковать в репозитории.
   - SESSION_SECRET: случайная строка не короче 32 символов.
   - APP_URL: основной HTTPS-адрес Vercel без завершающего слеша.
5. Выбери Production для переменных, разверни новый деплой.
6. Если Data API не видит созданные объекты, setup.sql содержит уведомление
   перезагрузки схемы; адрес Supabase и ключ должны относиться к одному проекту.

Секреты не присылай в чат, скриншотах и GitHub. Для новой случайной строки:
`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

## Разработка
`npm test` — API, защита, миграция, совместимость схемы, время и пересечения.
`npm run build` — проверка комплекта и номера сборки (без npm-зависимостей).
`npm start` — локальный сервер, `.env.local` только на своей машине.
Папка public содержит frontend; api/handler.js — Vercel function;
lib/handler.mjs и lib/store.mjs — сервер; seed.json — только для новой базы.
Не заменяй state в Supabase на seed.json при обновлении.

При следующем релизе синхронно обнови RELEASE / BUILD в app.js, version.json,
ссылки assets в index.html, список и имя cache в sw.js и package.json.
