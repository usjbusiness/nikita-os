NIKITA OS 5.0.0 — КАК ОБНОВИТЬ

ВАЖНО: это код для публикации, а не уже обновлённый сайт.
Никаких новых ключей, SQL-команд и нового проекта Supabase не нужно.

1. На старом сайте: Настройки → Скачать JSON-копию. Сохрани её у себя.
2. Распакуй Nikita-OS-5.0.0.zip на компьютере.
3. Открой подключённый к Vercel репозиторий GitHub, ветку main.
   В КОРНЕ репозитория должны лежать package.json и vercel.json, рядом
   папки public, api, lib, supabase, scripts, tests и остальные файлы архива.
   Не загружай ZIP как один файл. Не создавай вокруг кода ещё одну папку.
4. Add file → Upload files. Перетащи содержимое распакованного архива
   (включая папки целиком), замени существующие файлы и нажми Commit changes.
   Если GitHub не даёт загружать папки через браузер — используй GitHub Desktop.
   ОБЯЗАТЕЛЬНО загрузи public и scripts целиком, а также release-manifest.json.
   В прошлой загрузке новые корневые файлы пришли, а public осталась старой.
5. Vercel → проект nikita-os → Deployments. Должен появиться НОВЫЙ деплой
   с тем же последним коммитом GitHub. Дождись Ready.
6. Открой основной адрес: https://nikita-os-azure.vercel.app/update-check.html
   Там должно быть: «На сервере: 5.0.0 · nos-5.0.0-compact».
   Номер 5.0.0 также виден внизу сайта и на экране входа.

ЕСЛИ ПО-ПРЕЖНЕМУ СТАРЫЙ ДИЗАЙН
— Если update-check.html не найден или version.json не содержит 5.0.0,
  на этом адресе не опубликована новая сборка. Это не исправится чисткой кэша.
— В Vercel → Deployments → новый деплой → Source проверь коммит и main.
— Settings → Git: проверь, что подключён именно обновлённый репозиторий,
  а Production Branch — main (или ветка, которую действительно обновляешь).
— Settings → Build and Deployment:
  Framework Preset: Other
  Root Directory: пусто, если package.json / vercel.json лежат в корне
  Build Command: npm run build
  Output Directory: public
  Node.js: 24.x
— Если новый деплой Failed, открой Build Logs. Не меняй ключи наугад:
  пришли скрин ошибки сборки и блока Source, БЕЗ значений секретов.
— Если новый деплой Ready, но не Production: проверь production-ветку
  и Promote to Production для нужной сборки; открывай основной адрес проекта.
— Redeploy старого коммита заново соберёт старый код, а не новый из GitHub.

ЕСЛИ НА СЕРВЕРЕ УЖЕ 5.0.0, А В УСТАНОВЛЕННОМ ПРИЛОЖЕНИИ СТАРЫЙ ВИД
Сначала открой сайт в обычном браузере. Закрой и снова открой установленное
приложение. В версии 5 есть Настройки → Перезагрузить интерфейс.
Эта кнопка очищает только кэш оболочки Nikita OS, не данные Supabase и не вход.
Если старая версия не показывает её, можно проверить сайт в приватной вкладке:
это только диагностика кэша, старые вкладки вручную обнови после публикации.
Не удаляй данные в Supabase и не импортируй seed.json поверх своих данных.

ЧТО СОХРАНЯЕТСЯ
Задачи, события, ссылки, заметки, курсы и вход используют прежнюю базу.
Игра EHL переносится на 20 октября только один раз и только если исходная
запись ещё стояла на 21 октября. Вручную перенесённую игру не перезаписываем.
Расписание — исходный снимок 19–25 октября 2026 плюс твои добавления.
Полный семестр не выдуман; автоматической синхронизации с HOULI и Blackboard нет.
